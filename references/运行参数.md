# 运行参数

## 运行环境

在 Windows 上使用宿主已核实的本机 Python。读取组件和写入组件列在技能目录的依赖清单里。若本机缺少组件，先按宿主授权用同一解释器安装，再检查能否加载。技能本身不下载组件，不访问网络，不依赖其他技能目录。脚本从自身目录定位科目规则。

从技能目录运行时，以下命令中的 python 代表已核实的本机解释器。文件可位于任意目录，传入的文件路径用于本次运行，路径无需写进技能。

    python scripts/清洗账表.py --输入 "来源一.xlsx" "来源二.xlsx" --预检
    python scripts/清洗账表.py --输入 "来源一.xlsx" "来源二.xlsx" --输出目录 "交付"

无参数运行会在 Windows 打开文件选择和交付目录选择窗口。自动化调用应传入已选文件。接受普通和含宏的新版 Excel 工作簿，含宏文件按数据只读。鼎信诺还可直接读取具备已识别表头的旧版 Excel 和制表符导出文件。标准成品使用内置模板列序。

## 鼎信诺原始导出

1. 把原始序时账、科目余额表和配套的核算项目明细表、核算项目余额表一并传入「输入」。最多四份，按内容分类。只有一份主表时可以独立处理，辅助表须有对应主表。多个可用工作表需要确认范围。
2. 同一批应为同一公司及会计期间。鼎信诺源表未标明公司或起止月份时，从材料核对本次范围。可用「公司标识」传入已核实的公司，用「余额期间」传入已核实的起止月份，例如 2025-01~2025-12。参数与原余额标签冲突时需要核对；范围尚无证据时，跨表差异按参考列示。
3. 原表借贷方向是科目的自然方向。贷方科目的期初和期末转换为借方为正、贷方为负的净额，发生额保持原列和正负号。科目汇总按末级核对，上级原行及方向保留在「辅助匹配」。辅助明细按科目、选定维度和对象分组，余额表同一科目的选定明细及未列明差额须能对回科目汇总。
4. 按科目保留核算项目余额表中所选维度的原项目金额。某科目没有所选明细时，从同公司、同期间的序时账和核算项目明细查找补录依据。逐科目的借方、贷方发生额分别吻合，且原科目的期初、发生额、期末能对上时，按已唯一匹配的本期项目展开。辅助项目只覆盖部分分录时，仍可补入已核实部分，其余发生额和未知归属的期初列为未列明。此时对象行的期末是分配的本期净变动。主余额表自身异常时，保留差额及源行，另有可靠独立控制数才考虑重建。
5. 两个源维度都能满足所需业务口径但无法取舍时，用户确认后在科目规则文件用「鼎信诺:原表维度名」指定唯一来源。未登记的辅助编码保持空白，按原始的对象名称及来源位置核对。鼎信诺旧版文件的格式不满足识别要求时，先查看结构，再另存为新版 Excel 或依据已验证的方向与范围制作可追溯中间表。

## 陌生账表如何适配

1. 先直接预检。程序可识别十段账户组合，也可识别独立的科目编码、科目名称、部门、项目、开户行、银行账号、往来对象和相应编码。分列的科目行要能确定公司标识，可以来自公司的编码列、名称列、表头中明确写出的公司或账套标识。清理时不要把多个公司的明细合并。
2. 自动识别不成时，Agent 先自行查看结构。输出为原表页名、合并范围、原始行号、列字母、样例值和未计算公式位置。先看少量样例，必要时增加样例行数或针对某个候选区段读取原表。

       python scripts/清洗账表.py --输入 "另一种报表.xlsx" --查看结构 --样例行数 25

3. 依据标题、数据和原表合计，记录本次采用的页、表头末行、字段和列。直接用原文件预检，确保金额方向、公司范围和资料期间确定。Agent 负责填写本次方案，能从材料确定时可自行继续。方案示例如下，文件名和列号均为模拟值。

       {
         "另一种报表.xlsx": {
           "类型": "余额表",
           "工作表": "明细",
           "表头末行": 5,
           "公司标识": "模拟账套",
           "会计期间": "2025-01~2025-12",
           "列": {
             "科目编码": "A", "科目名称": "B",
             "期初": "D", "借方": "E", "贷方": "F", "期末": "G",
             "银行": "H", "银行账号": "I", "往来": "J", "往来编码": "K"
           }
         }
       }

       python scripts/清洗账表.py --输入 "另一种报表.xlsx" --版式方案 "本次版式.json" --预检

   以文件名为索引，允许只为一份文件写方案。字段可用下文的名称，以及公司编码、部门编码、子科目编码、产品编码、项目编码、往来编码、客户、客户编码、供应商、供应商编码、个人、个人编码、银行编码、银行账号、贷款银行、贷款银行编码、合同编码。序时账加日期和凭证号，有一级列时可增加一级编码、一级科目。余额表可以用期初借方加期初贷方、期末借方加期末贷方代替净额列。表头末行指最后一行列名或单位行。公司标识是分列表缺少公司列时的后备值，使用前应有原表或用户说明支持。余额表的期间要与原表证据一致。方案保存在本次工作目录，与原表和行号一起核对。

4. 部门、项目、客户等即使只有名称也可进入结果，缺少可区分对象的编码时逐行保留。按科目确认客户、供应商或职员的角色。贷款利息优先核对来源明确的贷款银行，普通项目编号不用来匹配借款合同。老账表用银行内部编码、新账表用实际账号时，完整开户行和账号在两表唯一可对应后才用同一身份核对。
5. 遇到列映射之外的结构，例如把方向和金额写在两列，Agent 可在方向、单位和范围有明确依据时先做可重跑的中间转换。保留原表与中间表的行号对应，单独用原表核对各方向和各期间金额，再跑本技能。保留对账证据，避免把中间表行号误作原表行号。证据不足时才向用户说明缺什么。

## 歧义处理

- 文件内有多个候选工作表时，确认选择后使用「工作表」指定单个输入的页名。两份文件各要指定工作表时，以「序时账」或「余额表」传入文件，再用相应的「序时账工作表」或「余额表工作表」指定。两份同类型输入先确认实际范围。
- 改名导致表头识别失败时，确认含义并提供表头别名文件。字典的键是内部字段，下列字段可配置。文件以通用文本编码保存，可以带字节顺序标记。

      {"组合":["总账账户键"],"借方":["记账本位币借方发生金额"]}

  带上「表头别名」参数。常用内部字段为：组合、描述、科目编码、科目名称、日期、凭证号、摘要、凭证类型、期间、公司、部门、子科目、产品、项目、往来、银行、借方、贷方、期初、期末、期初借方、期初贷方、期末借方、期末贷方。支持按本位币选择金额。表头很靠后时，可提高「表头扫描行数」，默认扫描每张工作表的前一百二十行，并组合最多四层表头。
- 已有两个同名候选列时，向用户说明文件、工作表、字段和候选列。如 B 列是确认的序时账借方，指定列文件写法如下。带上「指定列」参数。它只用于已识别的字段，无法识别的字段先补表头别名。

      {"序时账":{"借方":"B"}}

- 新科目无可验证规则时，将该科目的编码、名称以及原表已有维度交给用户选择。确认后提供自定义规则文件并带上「科目规则」参数。常用取值来源是段号（部门为三、子科目为五、项目为七、往来为八）。固定值适用于从科目名称确认的属性。

      {"0001000101":["示例科目名称","归属部门",3],"0001000102":["示例科目名称","业务类别","literal","示例业务"]}

  其他自动来源为会计年度（year）、贷款本金贷款行（loan）、借款利息匹配贷款行（interest）。科目名称须与原表相符。固定取值的辅助编码使用科目编码，该值可稳定追溯到内置规则。
- 带有效小数的金额超过默认两位时，核对真实精度后用「金额小数位」选择零到六位。未保存的公式结果需要在 Excel 重算后保存。检测到表头用万元等单位时，先确认单位和换算法，按批准的换算得到以元为单位的另存源件后再跑。原工作簿不改。
- 分属不同账套、币种或期间的源表，先确认对应关系。有业务行缺记录时，已确定的待核口径包括「往来未记录」「项目未记录」和「贷款银行待核」。手工补值需有客户明细、合同或贷款台账等证据。

## 输出约定

程序退出成功时会打印最终成果目录。每次生成新的子目录。发生写出或回读错误时，未交付的现场目录带「处理中」标记，不能把里面的文件交付使用。

序时账的凭证类型优先取明确的凭证类型或凭证类别字段，源表没有时留空。正式输出保留借、贷两列和原始红字。余额表的期初、期末为借正贷负的净额，分别写入模板的对应借方列，贷方余额列保留为空；期中借、贷独立求和。余额表的空白隔列保留，辅助核算名称已直接写在有标题的列。

核对表逐源行给出结果表行号，余额表多个源行可指向同一个结果行。跨表核对比较借贷发生额，列出科目级和辅助核算级差异。对齐检查依据是公司编码和会计期间，账套、重分类和文件范围需要结合报表来源判断。
