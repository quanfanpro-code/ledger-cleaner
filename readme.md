# 🧹 账表清洗

把鼎信诺以及其他财务系统导出的账表整理成同样的 Excel 格式。序时账固定 12 列，科目余额表固定 11 列。借方发生额和贷方发生额分开，每个科目只用一个辅助核算维度。比如银行存款看开户行和账号，应付账款看供应商，管理费用看归属部门。

## 🚀 把压缩包发给 Agent 就能开始

**把「账表清洗技能.zip」原样发给 Agent。** 解压、检查运行环境、找安装位置和验证能否使用，都交给 Agent。

### 想先装好，以后再用

上传压缩包，再把下面这句话发给 Agent。

> 这是「账表清洗」技能。请解压并检查运行环境，按你支持的方式安装，再验证能否运行。只有需要我授权或补充信息时再问我。

以前装过单独的鼎信诺清洗技能时，可以请 Agent 停用旧入口，今后统一使用「账表清洗」。

### 现在就要清洗

把**压缩包和要处理的 Excel 源表**一起发给 Agent，再说这句话。

> 请解压这个技能包，用它判断我发的是序时账还是余额表，整理成借贷两列。遇到新表样请先自行分析，每个科目仍保留一个辅助核算维度。只有关键口径无法从资料确认时再问我，处理完把结果和核对表发给我。

可以只发序时账或余额表，也可以一起发，文件名和顺序随意。鼎信诺如果另外导出了「核算项目明细表」和「核算项目余额表」，把它们和相应主表一起发。每批用同一家公司、同一个会计期间的资料。

安装后，发来源表并说「用账表清洗处理」即可。需要从技能列表选中它时，可搜索「账表清洗」或技能标识 ledger-cleaner。

### Agent 会依次做什么

1. 解压技能包，检查本机能否运行。如果缺少必要组件，会按当前环境的权限处理，确实需要你授权时才来问。
2. 按你的用途安装技能或在本次任务里直接运行，再用程序预检源表。需要你选择时，会说明具体文件、工作表、行列位置和候选项。
3. 生成结果和清洗核对表。拿到结果后，先看核对表的「金额核对」，再看「待核记录」。

这套程序在 Windows 上运行。请选择能读取附件、解压文件并运行本机程序的 Agent。如果当前 Agent 权限不足，让它说明具体卡在哪一步。

## 📂 哪些原表可以处理

- 新版 Excel 工作簿可以直接读取。鼎信诺还可以直接读取常见的旧版 Excel 和以制表符分隔的导出文件。鼎信诺先前生成、已带「辅助核算信息」的账表也可以作为输入。
- 科目及辅助信息可以写在十段账户组合里，也可以在不同列里。两份表的写法可以不同。序时账需要能找到记账日期、凭证号和本位币借贷金额，余额表需要能找到期初、发生额和期末。
- 表头前面可以有封面文字、标题、空行和单位说明。列可以换位置，表头可以有换行、同义写法、横向合并或纵向合并。
- 程序默认找每张工作表的前一百二十行，最多组合四层表头。表头实际更靠后时，告诉 Agent 大概在哪一行即可。一个文件里出现多张都能处理的候选工作表时，请告知实际要用哪张。
- 余额表的期初、期末可以是带正负号的净额，也可以是分别列出的借方和贷方。源表同时提供两种写法时，Agent 会先核对要用哪组金额。

## 🔎 程序是怎么清洗的

### 先找表，再找列

程序看表里的列名和表头结构，自动判断文件属于序时账还是余额表。它会还原合并表头的上下关系。例如「本位币」跨着下面的「借方」和「贷方」两列，即使同一张表另有原币列，也能依照上层标题定位本位币金额。

### 📎 鼎信诺的四张表怎么配

| 原表 | 用来做什么 |
|---|---|
| 序时账 | 提供每笔凭证分录及原始借贷金额 |
| 核算项目明细表 | 用日期、凭证、科目、可用的分录编号和金额，找到这笔分录的辅助项目 |
| 科目余额表 | 提供各科目的账面期初、借贷发生额和期末 |
| 核算项目余额表 | 提供客户、供应商、银行账户等辅助对象各自的余额和发生额 |

辅助表是配套资料。只有主表也可以先出表，能从主表取得的辅助信息照常保留。辅助明细能唯一匹配时，同一维度的多个对象会按各自名称显示在原分录的辅助列，各对象金额在核对表的「辅助匹配」里看。候选分录有多个时，Agent 会说明哪一行需要确认。

辅助余额表是空表时，程序会先核对公司、期间、科目发生额和分录辅助归属。证据齐全时，余额表列出已知的本期发生额及其净变动，无法归属的期初金额放在「未列明辅助项目」。没有足够证据的科目保留原科目汇总。

### 🧭 新报表长得不一样时

原样发给 Agent 就可以。比如新系统把「开户行」「银行账号」「客户名称」和「供应商名称」分别放在四列，Agent 会先检查这些列对应的业务含义。表头写法特殊时，它会查看原表的工作表、列位置、合并表头和少量样例，确定本次应该读哪张表、哪些列。然后由清洗程序按这个对应关系处理整张表，再回读核对。

银行存款仍按开户行和账号整理。应付账款里的往来项仍取对应的供应商。一张表用银行内部编码、另一张用实际账号时，程序会检查完整户名和账号能否唯一对应。两份报表都能指出各行的来源时，可以一起做跨表核对。

只有公司范围、借贷口径或某科目的辅助核算项无法从资料确认时，Agent 才会提出具体问题。收到结果后，可以在核对表的「字段定位」看到这次读取了哪些列。

### 每个科目只选一种辅助核算

| 科目 | 结果里显示什么 | 取值做法 |
|---|---|---|
| 银行存款 | 开户行和账号 | 读银行账户明细或开户行及账号列 |
| 应收、应付、预付、预收等往来科目 | 往来单位或个人 | 读往来段或按科目选对应的客户、供应商、职员列 |
| 开发成本、房产销售收入及成本 | 开发项目 | 读项目段或独立的项目列 |
| 应付职工薪酬、管理费用明细 | 归属部门 | 读部门段或独立的部门列 |
| 固定资产、累计折旧 | 资产类别 | 从科目名称取，例如「运输设备」 |
| 分税率的增值税进项税额 | 税率档 | 从科目名称取，例如百分之十三 |
| 长期借款本金 | 贷款银行 | 取本科目往来段登记的贷款行全称和编码 |
| 应付长期借款利息 | 贷款银行 | 读单独登记的贷款银行，或者按公司和合同编码唯一匹配本金 |

技能带有三百零一个科目的现成规则。新增科目会先按科目性质和源表已有信息匹配。例如「固定资产－运输设备」可以按运输设备归类，鼎信诺的销售费用也可以按实际登记的门店归集。同一个科目在序时账和余额表中使用同一维度。遇到来源中有多个候选维度、无法确定应保留哪个时，Agent 会列出候选项请你确认。

### 序时账逐笔保留，余额表按维度归并

序时账的每条原分录仍占一行，日期、凭证号和摘要随分录保存。借方、贷方分别写入，原表里的红字仍在原方向上显示为负数。

余额表按公司、科目和所选辅助项目汇总。同一个账号拆成几行、各行只是在往来对象上不同，清洗后可以合成同一个银行账户。模板中的期初和期末沿用带符号净额，填在各自的借方余额列。借方余额为正，贷方余额为负，旁边的贷方余额列留空。重分类科目保留原编码。

鼎信诺同时给出科目汇总和辅助明细时，总额以「科目汇总」为准。展开某个科目时，把该科目的「辅助明细」和「未列明辅助项目」放在一起看。源表的上级科目金额保存在核对表「辅助匹配」中。账户组合原表如果仅有明细，结果按明细层核对总额。

### 最后回读核对金额

程序会算出原表金额和结果金额，再打开写好的文件逐行核对。两张源表同时提供时，还会按科目及辅助项目比较借贷发生额。原始账套或重分类口径有差异时，源表之间可能有差额，核对表会保留差额和涉及科目。

## 📦 会拿到哪些文件

| 文件 | 怎么用 |
|---|---|
| 序时账-借贷两列.xlsx | 查单笔分录、凭证号和借贷金额 |
| 余额表-借贷两列.xlsx | 看每个科目及辅助项目的期初、发生额和期末 |
| 清洗核对.xlsx | 看读到了哪个工作表、金额是否一致、有哪些待核项，以及具体来自原表哪一行 |

**序时账从左到右 12 列**

日期、凭证类型、凭证号、摘要、科目编码、科目名称、借方金额、贷方金额、辅助核算编码、辅助核算名称、一级编码、一级科目。

**科目余额表从左到右 11 列**

科目编码、科目名称、辅助核算编码、辅助核算名称、期初余额(借方)、期初余额(贷方)、累计发生额(借方)、累计发生额(贷方)、期末余额(借方)、期末余额(贷方)、行类型。

只提供其中一种源表时，收到该种结果和清洗核对表。每次运行会生成一个新结果文件夹，旧结果和原始账表不会被覆盖。

## 🛠️ Agent 问我时，我该怎么回答

- **同名列或多张工作表。** 告诉 Agent 哪张工作表、哪一列是你要出表的口径。例如「用科目明细页的 B 列作借方」。程序可以按确认的列继续，无须手动改原表。
- **新科目该取什么。** 用日常业务语言说明，例如「这个科目按楼盘项目归集」。Agent 会把确认内容作为本次规则再预检。
- **原表没有客户或银行。** 已有明确取值规则的记录可继续清洗。缺客户标为「往来未记录」，利息不能唯一匹配贷款行时标为「贷款银行待核」。金额及原始行位置保留。有可靠客户明细或贷款资料时，可以交给 Agent 核对。
- **公式没有保存结果。** 请在 Excel 中打开对应源表，重新计算并另存一份，再提供新文件。Agent 报出的单元格就是需要检查的位置。
- **金额单位或精度不清楚。** 先确认源表是元还是万元，以及金额实际保留几位小数。Agent 会按你确认的口径处理。
- **跨表有差额。** 在核对表看「金额核对」和「跨表科目差异」。先看每张表清洗前后差额是不是零，再检查两份源表的账套、期间和重分类范围是否一致。
